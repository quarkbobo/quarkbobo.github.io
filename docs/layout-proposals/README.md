## 最值得改的5处

### 1. 首页的内容入口过晚出现

**实测：** 原站1440×1000下“最新记录”从文档Y=1001px开始。A为704.8px，B为463.6px；390×844下原站为732.4px，A为735.1px，B为454.4px。A手机的原始起点几乎没变，不能声称所有视口都提前。

**方案：** A保留先看星球的节奏；B桌面文章与星球并置、手机先最近记录再星球。原导航没有`aria-current`，两套原型增加当前位置样式和语义；关于仍跳到作者的“关于我”目录，不伪造个人简介。

**判断：** A更贴近现有深空气质；B更重视经常访问的人。这是审美与使用倾向判断，尚无用户行为数据。

证据：`evidence/baseline/report.json`、`evidence/visual-metrics.json`、`home-a.html` / `home-b.html`的不同DOM分组；前后首页截图在compare中。

### 2. 最近更新和目录重复，却没有各自的侧重点

**实测：** 原站6张等权卡片之后又列6个目录标题；只有V4卡片有真实摘要，其余5篇摘要为空，卡片上也没有真实分类标签。原卡片首行高约268px（桌面）/278px（手机）。

**方案：** 最近区域保留最近两篇和原有完整摘要；全部6篇在作者原有3组目录中完整可达，不隐藏旧文。标题露出由12次变8次。最近区域从1141.1px/1578.6px变为306.5px/375.2px（桌面/手机），**这包含6篇改为2篇的结构变化，不能当作单卡压缩比**。

主题目录起点：桌面2142.1→1011.3px，手机2311.0→1110.2px。找到一篇已知文章仍可直接点标题；没有新增搜索或强迫多层展开。目录组不是Hexo分类chip，不伪造分类属性。

证据：`content.json`的posts/catalogue、`evidence/supplemental-captures.json`、compare的最近记录和主题目录图。NEW原始规则为发布72小时内；这批文章在取证日均已超过72小时，原型不手工给旧文贴NEW。

### 3. 阅读页标题太大，无目录文章仍占双栏框架

**实测：** V4原站桌面标题84px、正文Y=543.5px；A标题46px、760px阅读栏居中，正文Y=416.1px。手机原站正文Y=354.2px，原型为401.8px，**原始值晚47.6px**。原型额外的方案条约68.6px，不能把隐藏方案条后的推算冒充生产实测。

**方案：** 无目录文章居中；有目录文章保留桌面右侧sticky目录，手机正文之前原生details默认收起。完整正文、标题anchors不删改。新增当前位置和原文链接需要空间，所以不以正文起点越小越好来判断。

**待实施验证：** 若选定A，再在真实站点的页头中复核手机首屏。当前原型没有证明手机首屏在生产环境下已经改善。

证据：两份完整body与原DOM文本、heading IDs对照；最终验证中的文章/目录键盘场景；compare的两种阅读页同尺寸图。

### 4. 归档需要更清楚的时间分组

**实测：** 现有7条归档，原站没有年分组。A按实际生成页日期分为2026和2025，统一月日列，长标题自然换行；7条全部保留，包括“博客目录”和两篇最早文章。

**方案：** 年份入口可直达该段，每篇仍一次点击打开；不为7条数据新增搜索系统。

**来源边界：** “博客目录”源文件没有作者填写日期，2026年4月26日是这次生成页提供的日期；不把它解释成已确认的写作时间。

证据：`content.json`的archive、`archive.html`、前后归档截图。

### 5. 游戏入口难以辨认和触达

**核实纠错：** 任务书所称“5个链接”不准确，原始Markdown和生成DOM均为4个：贪吃蛇CTF、2048、中国象棋、国际象棋。“贪吃蛇CTF”是一个完整链接。

**方案：** 4个整卡入口，保留原名、精确href和新标签页行为；所有入口大于44px。常规手机图标与标题对齐，200%字号下自动上下排列。打开游戏仍一次点击；未重做游戏应用。

证据：`content.json`的games.links、最终验证4个精确href/标题对照和普通/200%截图。

## 视觉规则和取舍

色盘、字体、间距和两套结构图见`DESIGN.md`。以原站冷蓝星球和暖金星环为主，中文宋体负责A的标题，系统中文黑体负责正文；B用黑体和更紧凑的间距。没有生成封面、虚构统计或额外动态背景。

星球截图来源、完整取景范围和取证方式见`assets/planet-source.json`。仅在一次性取景浏览器隐藏覆盖在星球左缘的首页文案，未改canvas、模型、相机或生产文件；原型CSS只柔化截图周围空白边缘，完整星球和星环保留。

采用frontend-design审美流程，并按[Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)核查原生控件、焦点、响应式和减少动态。此引用是设计检查依据，不是原站问题的外部证据。

## 选定后的实施顺序

1. 页头当前位置、阅读栏与目录：先统一导航和阅读基础。
2. 最近两篇与完整主题目录：让近期更新和按主题查找各有作用。
3. 归档时间分组、4个游戏入口：收益明确、局部改动。
4. 按最终A/B选择接入真实星球构图：必须重新验证点击进入、返回及手机衔接，不能把这次静帧当成通过证据。

尚待选择：A还是B，以及展示/阅读的优先级。未排除：不同系统的中文字体差异；真实3D接入后的构图与运动感；移除方案工具条后真实手机首屏；未做真实读者查找实验。本轮无需新插画或安装依赖。
