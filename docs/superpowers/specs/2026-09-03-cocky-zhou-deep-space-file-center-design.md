# COCKY ZHOU 深空文件中心设计

## 目标

把 `source/COCKY ZHOU/index.html` 从红白通用文件列表改造成“蓝色空间号”体系中的独立资料舱。页面继续从 GitHub API 读取 `source/files`，保留搜索、类型筛选、打开和下载能力，并删除页面下方的 Markdown 推文预览功能。

## 视觉方向

采用“深空资料舱”方案。页面以安静的深蓝空间为底，文件列表像悬浮在舱内的资料面板。视觉身份继续保留 `COCKY ZHOU`，但糖果式红色 Hero 改成空间信号站语汇。

色彩令牌：

- 深空黑 `#02040B`：页面底色。
- 舱体蓝 `#08162A`：主要面板与文件行。
- 信号蓝 `#38BDF8`：主要操作、焦点与选中状态。
- 星云紫 `#8B5CF6`：粒子、渐变和次要强调。
- 正文白 `#E8F2FF`：标题与主要信息。
- 雾蓝灰 `#91A8C4`：说明、文件大小与辅助信息。

显示标题使用收窄、偏科技感的系统无衬线字体序列，正文保持中文系统字体以保证清晰度；文件扩展名、计数和状态标签使用等宽字体。页面不依赖新的字体网络请求。

## 页面结构

页面保持单列、响应式布局：

```text
┌──────────────────────────────────────────────┐
│ 返回蓝色空间号       COCKY ZHOU / DATA BAY  │
│ 文件信号站标题、说明、在线状态与文件计数      │
│ 稀疏粒子背景 + 一道横向信号轨迹               │
└──────────────────────────────────────────────┘
          ┌────────────────────────────┐
          │ 搜索框                     │
          │ 全部 / TXT / XLSX / MD     │
          │ 文件行：名称 / 大小 / 操作  │
          └────────────────────────────┘
                    页脚
```

桌面端内容宽度约 960 像素。移动端文件操作按钮允许换行并保持至少 44 像素点击区域。首页链接置于 Hero 顶部，用户可以回到“蓝色空间号”。

## 标志性元素与动画

标志性元素是一条横穿 Hero 的“信号轨迹”：细蓝光线在低密度星尘之间缓慢扫过，表达文件从 GitHub 进入资料舱。背景粒子借用博客已有的蓝紫粒子语言，但在此独立 HTML 中使用轻量 Canvas 实现，不复制首页的行星场景。

鼠标在支持精细指针的设备上产生短暂蓝紫拖尾。背景粒子、信号轨迹和鼠标拖尾都尊重 `prefers-reduced-motion`；触摸设备不启用鼠标拖尾，标签页隐藏时停止动画。

## 文件交互

- 页面加载时继续请求 GitHub Contents API，并按中文文件名排序。
- 搜索和文件类型筛选保留，筛选结果实时更新文件计数。
- 每个文件只提供“打开”和“下载”。Markdown 的“打开”也直接访问发布后的 `/files/<文件名>`，不再在页面内渲染。
- 删除“推文预览”卡片、Markdown 标签栏、`marked.js` 依赖、预览状态与 Markdown 渲染函数。
- 加载、空结果和错误状态使用资料舱状态提示，不使用内联红色样式。
- 动态插入的文件名继续进行 HTML 转义；文件 URL 继续通过 `encodeURIComponent` 构造。

## 可访问性与兼容性

- 页面包含跳到文件列表的跳转链接和清晰的主内容地标。
- 搜索框有可访问标签，筛选按钮暴露当前选中状态。
- 所有交互控件提供可见的 `:focus-visible` 样式。
- 装饰 Canvas 对辅助技术隐藏，并且不能截获鼠标事件。
- JavaScript 或 Canvas 不可用时，基础页面结构仍可阅读；GitHub API 错误会显示可操作的刷新提示。
- 保持单文件部署，不新增构建步骤或第三方运行依赖。

## 验证

- 静态检查页面不再包含推文预览、预览按钮、`marked.js` 或 Markdown 渲染逻辑。
- 在本地 Chromium 中打开生成后的 `/COCKY ZHOU/`，验证文件读取、搜索、筛选、打开与下载。
- 检查桌面与手机宽度下的布局、键盘焦点、减少动态效果和 Canvas 降级行为。
- 运行现有完整构建与测试，保证该独立页面仍由 Hexo 原样复制，且脚本语法有效。
