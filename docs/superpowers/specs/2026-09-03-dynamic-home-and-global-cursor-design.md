# 动态首页、三日新帖与全站鼠标拖尾设计

## 目标

- 修复本地内容已推送但 GitHub Pages 未更新的问题，使 `Bobo一键更新` 上传后的有效内容能够通过 CI 并发布。
- `source/_posts` 下除特殊文件 `博客目录.md` 外的所有 Markdown 文章都能进入首页“最新记录”，文章所在一级文件夹可以自由增加、删除或改名。
- 首页卡片只显示作者按约定写出的第一段文字，并根据卡片可见高度自动省略。
- 发布时间距访问时刻不超过 72 小时的文章显示 `NEW` 标记，并位于普通文章之前。
- 鼠标拖尾在首页、文章、归档及其他主题页面中都可用。
- 更新首页标题、副标题、导航和页脚文案。

## 方案选择

采用构建时生成内容、浏览器只处理时效状态的方案。

一键更新脚本负责扫描当前文件结构并生成目录；Hexo 模板负责提取摘要和输出文章卡片；浏览器根据访问时刻判断 `NEW` 是否仍在 72 小时内。相比给每篇文章手写 `summary`、`category` 字段，这个方案保留了一键更新体验。相比在浏览器中解析整篇 Markdown，生成结果更稳定，页面加载时也不会出现内容闪烁。

## 首页文字与导航

- 主标题由“在噪声里，保留信号。”改为“蓝色空间号”。
- 主标题在常见桌面和手机宽度保持单行，使用响应式字号填满可用宽度，保持醒目、清晰且不横向溢出。
- 副标题由“技术笔记、游戏实验与日常观测。”改为“技术笔记、游戏合集、日常Vlog”。
- 顶部导航移除“分类”和“标签”，保留“首页”“归档”“关于”。
- 页脚文字由“持续记录，保留可复访的信号。”改为“不要回答！不要回答！不要回答！”。

## 动态文件夹与文章目录

`Bobo一键更新` 每次运行时递归扫描 `source/_posts`，不再维护“个人博客”“技术教程”“游戏相关”“关于我”等写死列表。

- 每个一级子文件夹自动成为首页“博客目录”的一个分组，分组名称就是当前文件夹名称。
- 一级文件夹按稳定的自然名称顺序输出；文件夹内文章按标题排序，避免同一内容在不同电脑上产生随机顺序。
- 更深层级的文章归入它所属的一级文件夹，链接保留完整相对路径或文章 front matter 中的 `permalink`。
- 直接放在 `_posts` 根目录的文章归入“未分类”。
- 特殊文件 `博客目录.md` 只负责首页目录内容，不作为普通文章卡片显示。
- 支持 `.md`、`.markdown` 以及现有目录生成器已经支持的独立 `.html`、`.htm` 条目；首页“最新记录”只显示 Hexo 识别为文章的内容。
- 文件夹被删除或改名后，下一次运行会从生成的目录中移除旧分组和旧链接，并加入当前分组。

## 首页摘要规则

摘要从 Markdown 原文读取，不从渲染后的整篇 HTML 截断。

1. 移除 YAML front matter，并跳过其后的空行。
2. 查看第一个非空内容块。只有这个内容块的首行以一个字面 Tab 或至少四个普通空格开头时，才将其认定为首页引导段落。
3. 允许段落开头在缩进前带 UTF-8 BOM 或零宽字符，以兼容现有文章中的不可见字符；这些字符不会显示在摘要中。
4. 收集到下一个空行为止的同一段文字，移除每行的一层约定缩进，再去除 Markdown 链接地址和不适合摘要的标记，只保留可读文字。
5. 如果第一个内容块是未缩进正文、标题、引用、列表、图片、代码、HTML 或其他格式，首页不显示该文章摘要，也不会继续寻找后面的段落。
6. 模板不再按固定字符数裁剪。摘要区域使用响应式多行截断，文字随着卡片宽度自然排版，超出可见行数时在末尾显示省略号。

该约定会使目前带 Tab 首行缩进的文章显示引导文字；没有 Tab 或四空格首行缩进的文章不会显示摘要。

## 三日新帖与 `NEW` 彩带

- 文章卡片输出标准化发布时间，首页脚本用访问设备当前时间计算发布时间差。
- 发布时间满足 `0 <= 当前时间 - 发布时间 <= 72 小时` 时，卡片进入新帖状态；未来日期不会提前显示为新帖。
- 所有仍在 72 小时窗口内的文章排在普通文章之前，新帖之间继续按发布时间从新到旧排列。
- 新帖卡片右上角放置一条从左上向右下倾斜的红色彩带，文字为清晰的大写 `NEW`。彩带使用深红到亮红的渐变、细窄高光和适度阴影，与深色太空主题保持对比，同时避免遮挡标题和日期。
- JavaScript 不可用时，页面仍按发布时间顺序显示文章；动态彩带默认保持隐藏，避免静态构建数日后继续错误显示 `NEW`。

## 全站鼠标拖尾

现有拖尾从首页星球场景中拆成独立的全站组件：

- 拖尾专用样式在所有主题页面加载，拖尾 DOM 和两个脚本也由全站布局统一输出一次。
- 桌面细指针、支持悬停且未开启“减少动态效果”时启用；手机、触摸输入和减少动态效果继续禁用。
- 首页存在星球场景时，拖尾继续响应“暂停背景动态”和场景降级状态。
- 文章、归档等内页没有星球场景时，拖尾只受输入能力、页面可见性和减少动态效果控制。
- 固定八节点池、动画结束回收、窗口失焦清理和销毁逻辑继续保留，不因全站加载而增加无界 DOM。

## 发布故障修复

线上未更新的直接原因是最近提交的 Hexo 构建成功，但 Node 测试仍写死已经删除的旧文章、旧分类/标签入口和旧图片清单，导致 GitHub Actions 在上传 Pages 构件前失败。

- 将文章页面测试改为使用测试目录中自带的独立夹具，不依赖任何可被用户删除的真实文章路径。
- 分类与标签入口已从导航移除，构建测试不再要求已被删除的 `/categories/`、`/tags/` 首页存在。
- 图片尺寸缓存仍验证配置结构和已配置尺寸是否合法，但不再要求缓存与某一批历史文章 URL 完全相等，从而允许日常增删文章。
- GitHub Pages 工作流继续在部署前执行测试；测试只拦截主题和生成器故障，不再因正常内容增删而失败。

## 测试与验收

- 在隔离仓库夹具中分别增加、删除和改名 `_posts` 一级文件夹，验证生成目录只包含当前结构且链接正确。
- 验证根目录文章进入“未分类”、深层文章归入一级目录、`博客目录.md` 不进入文章列表。
- 使用带 Tab、四空格、零宽字符、无缩进、标题、引用、列表和图片开头的 Markdown 夹具验证摘要规则。
- 验证首页不再包含固定字符截断，摘要样式具有响应式多行省略规则。
- 使用固定时钟验证 72 小时内、恰好 72 小时、超过 72 小时和未来发布时间的 `NEW` 状态与排序。
- 验证首页和至少一个文章页都只加载一个拖尾组件，并验证无星球场景的文章页可以产生拖尾。
- 验证导航、主副标题和页脚为新文案，分类与标签链接已移除。
- 运行 `npm run test:fresh`，确认干净构建和完整测试通过后提交并推送 `master`；再核对 GitHub Actions 成功以及线上首页包含最新提交内容。
