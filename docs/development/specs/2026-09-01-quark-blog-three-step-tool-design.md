# Quark 博客三步工具设计

**日期：** 2026-09-01
**状态：** 用户已批准方案 A

## 目标

将桌面 `Quark博客工具.lnk` 精简为一个面向日常发文的三功能入口：查看文章目录、更新文章目录、更新后安全上传 GitHub。成功完成的操作自动关闭 PowerShell 窗口；失败时保留窗口并显示可执行的错误信息。

## 菜单与行为

快捷方式继续启动项目内 `tools/quark-blog-tools.ps1 -Action Menu`，菜单仅显示：

1. **查看当前文章目录**：用资源管理器打开 `C:/Users/Lenovo/Desktop/Quarkbobo/source/_posts`。
2. **更新文章目录**：在固定项目根目录依次运行 `npm run clean` 和 `npm run build`，重新生成 `public/index.html`、文章日期、归档和分类等 Hexo 输出。
3. **更新并上传 GitHub**：先完整执行“更新文章目录”；只有构建成功后才进入现有安全发布流程。
0. **取消**：不执行操作并关闭窗口。

删除菜单中的“预览博客”和独立的旧“安全发布”入口。脚本内部可以保留可测试的 Build/Publish 单元，但用户菜单和公开动作只围绕上述三项。

## 更新并上传的数据流

第三项严格按以下顺序执行：

1. `npm run clean`。
2. `npm run build`。
3. 验证当前分支精确为 `master`。
4. 显示工作区、未暂存和已暂存变更摘要。
5. 第一次要求输入大写 `P`，随后执行 `git add --all`。
6. 显示最终暂存内容。
7. 第二次要求输入大写 `P`，有变更时创建普通提交，无变更时跳过空提交。
8. 执行普通 `git push origin master`，禁止强制推送。

构建失败时不得暂存、提交或推送。用户在任一确认处取消时，沿用现有安全语义：第一次取消不新增暂存；第二次取消保留已经暂存的内容。

## 窗口生命周期与错误处理

- 菜单操作成功、取消或发布确认取消后，脚本正常退出，由快捷方式窗口自动关闭。
- 任一步骤失败时返回非零退出码，显示原始失败阶段和恢复提示，并等待用户按回车后关闭。
- GitHub 的 SSH、权限或仓库连接失败时，本地提交不得回滚；提示用户修复连接后重试第三项。
- 不申请管理员权限，不修改全局 PowerShell 执行策略，不改变快捷方式的固定项目目录。

## 快捷方式

继续使用 `C:/Users/Lenovo/Desktop/Quark博客工具.lnk`，目标保持为 Windows PowerShell，参数保持指向项目内脚本的 `-Action Menu`。只更新描述文字，使其准确表达“查看文章、更新目录、更新并上传”。旧 `Quark一键更新.lnk` 不参与新流程；除非用户另行要求，本次不删除它。

## 测试与验收

自动测试必须证明：

- 菜单只显示三项业务功能和取消项，并分派到正确动作。
- 更新动作严格按 clean → build 执行，clean 失败时不运行 build。
- 更新并上传严格按 clean → build → Git 预览/确认/提交/普通推送执行。
- clean 或 build 失败时没有任何 Git 暂存、提交或推送调用。
- 成功路径不调用暂停读取器；失败路径显示恢复信息并等待回车。
- 大写 `P` 双重确认、非 `master` 拒绝、无空提交、无强制推送等现有安全合同保持有效。
- 快捷方式仍指向正确脚本、工作目录和菜单动作。

手工验收仅执行无外部副作用的“查看当前文章目录”和“更新文章目录”。真实上传由用户使用第三项完成，自动测试使用替身命令验证顺序，避免验收过程意外推送。
