## 1. 目标

将现有 NexT 主题替换为独立的“流体粒子”Hexo 主题，主题目录为 `fluid-particle`，完整保留文章、页面、小游戏、工具和下载文件。网站要形成“深空档案馆”的个人识别度：蓝紫气态土星是唯一主视觉，粒子严格复现参考视频的多层弧形流动逻辑，正文阅读与性能优先于装饰。

网站的核心受众是阅读技术笔记、个人记录并体验网页小游戏的访客。首页的单一任务是让访客快速认识 Quark 并进入文章或实验内容。

## 2. 不变内容与范围

- 保留 `source/` 下的全部现有内容及其 URL 行为，包括文章、国际象棋、中国象棋、贪吃蛇、2048、图像转换器、静态文件和图片。
- 保留 Hexo 作为生成器，不迁移 React、Next.js 或其他站点框架。
- 移除主配置对 `next theme` 的引用，切换到新的独立主题。
- NexT 目录在验证新主题后从工作目录移除，但完整版本必须存在于重建前备份中。
- 不改写用户文章正文，不为了视觉统一删除或重命名现有内容。
- 不新增评论、账号、数据库、后台管理或网络分析功能。

## 4. 视觉系统

### 4.1 色彩

- `Void`：`#010208`，页面底色。
- `Deep Navy`：`#07101E`，卡片与浮层。
- `Signal Cyan`：`#67EAFF`，焦点、星环高光和粒子亮部。
- `Orbit Violet`：`#9568FF`，球体暗面与能量拖尾。
- `Ice White`：`#EAFBFF`，标题与关键文字。
- `Archive Blue Grey`：`#8DA0B7`，正文辅助信息。

正文与背景的颜色对比度至少达到 WCAG AA。半透明文字必须以最终合成颜色验算，而不是只看源色值。

### 4.2 字体

- 展示标题：`Iowan Old Style`, `Source Han Serif SC`, `Noto Serif CJK SC`, `Songti SC`, serif。
- 中文正文：`Microsoft YaHei UI`, `PingFang SC`, `Noto Sans CJK SC`, sans-serif。
- 数据标签：`Cascadia Mono`, `SFMono-Regular`, Consolas, monospace。

不依赖远程字体服务，避免中国网络环境下闪烁、阻塞或字体缺失。标题使用克制的宋体/衬线气质，数据标签仅表达日期、分类和系统状态，不做无意义装饰。

### 4.3 布局

桌面首页首屏采用 55/45 的非对称结构：左侧标题与简介，右侧土星；粒子弧从左下经过页面中下部，收束至右侧天体。文章列表从第二屏开始，进入内容区后显著降低背景亮度。

移动端调整为标题在上、土星位于右下并部分出界，粒子密度降低。导航使用可键盘操作的折叠菜单。最小适配宽度为 320px。

### 4.4 独特记忆点

唯一强视觉是“被蓝紫吸积流环绕的私人档案土星”。星球不是普通渐变圆：轮廓略扁，表面有水平气态条带、明暗终止线、纬向缓慢流光，行星环分前后层穿过球体。页面不再增加扫描线、HUD 面板、霓虹边框或大量状态数字，避免落入通用赛博朋克模板。

## 5. 参考视频粒子系统

参考文件：

`C:/Users/Lenovo/Documents/xwechat_files/wxid_uz6uj3dkp9t112_c034/msg/video/2026-08/b26aab7263f557c6aabc9389993c3049.mp4`

已确认的视频特征：1280×592、30 FPS、8.1 秒；背景主体基本稳定，运动集中在下半部；粒子不是均匀爆炸或跟随鼠标乱飞，而是沿多条同向弧线流动。

### 5.1 流向和层次

- 主流向：从画面左下进入，沿浅弧穿过中下部，再向右上方土星区域抬升。
- 慢速环境尘：约占 84%，点径小、亮度低、生命周期 12–25 秒，仅在短距离内可感知位移。
- 中速亮簇：约占 13%，成簇但不粘连，生命周期 6–11 秒，亮度随弧线位置缓慢变化。
- 高能拖尾：约占 3%，生命周期 1.8–3.4 秒，偶发出现长拖尾，不能连续刷屏。
- 至少三条相邻轨道带具有不同曲率、垂直偏移与速度；所有轨道保持同向，不围绕鼠标旋转。
- 粒子在视野边缘淡入淡出，重新进入轨道时不得跳变或闪现。

### 5.2 运动模型

轨道使用归一化三次 Bézier 曲线计算。粒子保存固定种子、轨道编号、相位、生命周期、尺寸和颜色，帧间只根据真实经过时间更新相位。随机参数只在初始化或重生时生成，绘制循环中不调用随机数。

鼠标输入经过阻尼后，只对轨道控制点施加很小的偏移：桌面最大 8px，移动端关闭。它改变空间呼吸感，但不改变左下至右上的总体方向。

页面不可见时暂停动画；重新可见时重置时间戳，避免一次性补算造成跳跃。

### 5.3 性能实现

- 使用单个全屏 Canvas 绘制粒子，CSS 图层绘制土星与静态星空。
- 用 `requestAnimationFrame` 跟随显示器刷新率，运动按 delta time 推进，而不是每帧固定步长。
- Canvas DPR 桌面上限 1.5，低性能或移动设备上限 1.25。
- 光点和光晕预渲染到离屏小画布；热循环内不使用 `shadowBlur`、渐变创建或 DOM 查询。
- 粒子按颜色与层级批量绘制，缓存数组长度、画布尺寸和常用属性。
- 只注册一个 `pointermove`、一个 `resize` 和一个 `visibilitychange` 监听器；不阻止默认行为的输入监听器使用 `{ passive: true }`。
- resize 通过 `requestAnimationFrame` 合并，非关键粒子预热使用 `requestIdleCallback`，并提供 `setTimeout` 回退。
- 根据最近 120 帧的移动平均耗时自动降低或恢复粒子数量，调整有滞后区间，避免质量频繁抖动。
- 主题脚本使用 `defer`，文章卡片使用 `content-visibility: auto` 与合理的 `contain-intrinsic-size`。

性能目标：常见 1920×1080 笔记本前台页面达到稳定 55 FPS 以上，移动端达到 30 FPS 以上；连续长帧比例低于 2%。最终以正式主题前台测试为准，不使用后台节流标签页数据。

### 5.4 动效降级

当 `prefers-reduced-motion: reduce` 生效时，Canvas 不启动持续动画，只显示静态星空、土星和少量固定粒子。页面内容、导航与链接在 JavaScript 失败时仍然可访问。

## 6. 页面与组件

### 6.1 全站框架

- `layout/layout.ejs`：语义化 HTML、跳到正文链接、全局导航、主内容和页脚。
- `layout/_partial/head.ejs`：SEO、视口、主题色、样式和 defer 脚本。
- `layout/_partial/header.ejs`：品牌与主要导航。
- `layout/_partial/space-scene.ejs`：只在首页渲染土星与 Canvas。
- `layout/_partial/post-card.ejs`：文章标题、摘要、日期和真实分类。

### 6.2 首页

首屏显示真实站点名称 `Quark's Blog`、文案“在噪声里，保留信号。”以及进入文章列表的明确链接。第二屏按 Hexo 当前排序显示文章。文章卡片悬停时只产生 2–4px 抬升、边缘微光和标题颜色变化。

### 6.3 文章页

正文最大宽度约 760px；强化中文段落行高、标题层级、引用、表格、图片和代码块。桌面目录作为粘性侧栏，窄屏改为折叠目录。文章页保留低亮度静态星空，不运行动画粒子，避免影响阅读和耗电。

### 6.4 归档、分类、标签和普通页面

归档使用时间轴但不使用虚构编号。分类和标签只显示真实 Hexo 数据。普通页面与现有独立 HTML 游戏继续按原 URL 输出，不强行套入主题 DOM。

### 6.5 错误与空状态

- 无文章：首页显示“档案中还没有记录”，并提供返回首页链接。
- 无分类或标签：说明当前没有对应内容，不显示虚构卡片。
- Canvas 初始化失败：隐藏画布，保留土星、背景和全部文字。
- JavaScript 禁用：导航保持普通链接可用，移动端菜单默认以可访问方式展开。

## 7. 可访问性和交互标准

- 使用 `header`、`nav`、`main`、`article`、`footer` 等语义元素和唯一的页面主标题。
- 所有交互由原生链接或按钮承载，提供可见 `:focus-visible`，不使用不可聚焦的 `div` 模拟按钮。
- 导航按钮具有可理解的名称、`aria-expanded` 和关联菜单 ID。
- 动效不承载唯一信息，不设置快速闪烁；高能粒子闪现频率保持低于安全阈值。
- 触控目标最小 44×44px；正文链接不只靠颜色区分。
- 图片使用现有替代文字；装饰性土星与 Canvas 对辅助技术隐藏。
- 支持键盘、触摸、鼠标和无悬停设备。

完成主题后，必须使用 `web-design-guidelines` 拉取最新规则，对主题 EJS、CSS 和 JavaScript 逐文件审查并修复高优先级问题。

## 8. 快捷入口整合

将桌面 `BoBo一键更新.lnk` 与 `Posts.lnk` 的用途整合为一个 `Quark博客工具.lnk`。新快捷方式指向项目内 PowerShell 启动器，并提供：

1. 打开文章目录 `source/_posts`。
2. 启动本地预览。
3. 构建网站。
4. 提交并推送到 `origin/master`。

推送流程先显示 `git status` 和待提交摘要；无变更时不创建空提交；使用普通 `git push origin master`，禁止 `--force`。失败时保留窗口并给出具体下一步。原两个快捷方式的目标、参数和工作目录写入备份记录；新入口验证后，原快捷方式移动到备份目录，不直接删除。

该入口不需要管理员权限。若 Windows 执行策略阻止脚本，只对快捷方式目标使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File <exact-path>`，不修改全局执行策略。

## 10. 验证与完成标准

- 备份存在，文件数和关键文件校验通过，并附恢复说明。
- `npm run clean && npm run build` 成功且无主题模板错误。
- 首页、文章、归档、分类、标签、关于页和现有独立页面均能访问。
- 站内导航与主要资源不存在失效链接。
- 320px、768px、1440px 和 1920px 视口无水平溢出或不可操作控件。
- 键盘可完成导航与菜单操作，焦点始终可见。
- reduced-motion 下不启动持续粒子动画。
- 粒子方向、层次、稀有拖尾与淡入淡出符合第 5 节；不出现重生闪现和鼠标改向。
- 正式前台性能测试达到第 5.3 节目标，或记录设备限制与自适应降级结果。
- `web-design-guidelines` 审查无未处理的高优先级问题。
- Git 差异不包含备份目录、生成目录或无关用户文件。
- `Quark博客工具.lnk` 的打开目录、预览、构建、普通推送均经过实际验证。

## 11. 技能应用边界

- `frontend-design`：用于视觉 token、排版、布局、唯一记忆点和构建后的截图自评。
- `web-design-guidelines`：用于完成后的最新规范审查，不替代浏览器与构建测试。
- `vercel-react-best-practices`：本项目不使用 React；只应用其框架无关的事件监听、脚本加载、热循环、空闲调度和长列表渲染规则。
